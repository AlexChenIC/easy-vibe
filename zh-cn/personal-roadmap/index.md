# Alex 的产品发布学习路线

你现在最需要的不是再学一遍“如何开始用 AI 写代码”，而是把已经做出来的一批原型，筛选、打磨、上线，并让陌生用户愿意打开、理解、试用和传播。

从教育设计角度看，最适合你的学习方式不是从头刷完 Easy-Vibe，而是采用“真实项目驱动”的路线：每看一节课，就立刻把它应用到你手里的一个产品上。学习的证据不是“看完了”，而是产出了一个能发布、能展示、能复盘的具体物件。

## 教育视角评估

我重新审查后，认为这套路线整体适合你，但原版路线还需要补强三点：

1. **先筛选项目，再补技术。** 你不是缺少想法，而是缺少判断哪个半成品值得进入发布流程的标准，所以需要把 JTBD、用户访谈、需求验证提前。
2. **把“看课”改成“交付证据”。** 每节推荐课都应该对应一个产出，比如一句话定位、核心流程图、可访问链接、反馈入口、发布短文、数据看板。
3. **把发布后的增长闭环补上。** 你想吸引流量和注意力，所以路线不能停在部署成功，还要覆盖技术写作、作品展示、数据埋点、开源协作和持续迭代。

因此，这页优化后的目标是：帮你从“会做 AI 玩具的人”，过渡到“能持续发布小产品、沉淀作品集、建立个人名气的人”。

## 使用方法

优先级分成三类：

- **必学**：直接对应你目前最大的卡点，建议先看。
- **选学**：根据当前项目类型选择，没用到时可以跳过。
- **加分**：能提高专业感、传播力或长期维护能力，但不用阻塞第一次发布。

学习时建议只选一个真实项目作为练习对象。不要同时救十个半成品，先把一个项目推到公网，再把方法复用到下一个。

## 路线总览

| 阶段 | 教育目标 | 你的阶段产出 |
| --- | --- | --- |
| 0. 项目筛选 | 从一堆半成品里挑出最值得发布的一个 | 1 个候选项目评分表和 1 个清晰定位 |
| 1. 产品化 | 把玩具变成陌生人能理解的小产品 | 核心流程、落地页、可试用 MVP |
| 2. 工程化 | 补齐上线、数据、稳定性和维护能力 | 公网链接、数据存储、反馈入口、发布检查表 |
| 3. 发布与增长 | 让作品被看见，并根据反馈迭代 | 发布短文、演示视频、数据复盘、下一版计划 |
| 4. 作品集与品牌 | 把多个产品变成个人品牌资产 | 个人主页、项目目录、代表作展示 |

## 0. 先筛选：哪个项目值得你投入发布？

目标：避免你继续在一堆“有趣但不成产品”的原型之间切换。先选一个最值得发布的项目，给它明确边界。

| 优先级 | 课程 | 你能学到什么 | 学完应产出什么 |
| --- | --- | --- | --- |
| 必学 | [找到好点子](/zh-cn/stage-1/finding-great-idea/) | 判断需求是否真实，区分痛点、爽点和痒点，把模糊 idea 改成更窄、更有购买或使用动机的产品方向。 | 从你的半成品里选出 1 个最适合发布的项目，并写出“谁在什么场景下为什么需要它”。 |
| 必学 | [用 Jobs to Be Done 找到用户真正想完成的事](/zh-cn/stage-1/appendix-jobs-to-be-done/) | 用“用户想完成的进展”替代功能堆叠，避免产品只是在展示技术。 | 1 条 JTBD 句子、3 个目标场景、3 个用户成功标准。 |
| 必学 | [The Mom Test：如何通过用户访谈验证需求](/zh-cn/stage-1/appendix-mom-test/) | 学会问过去事实、替代方案和真实成本，避免被“这个挺好我会用”误导。 | 5 个访谈问题、3 位潜在用户名单、一次访谈记录模板。 |
| 选学 | [双钻模型：先做对的事，再把事做对](/zh-cn/stage-1/appendix-double-diamond/) | 在发散和收敛之间切换，把“想加更多功能”变成“先定义最关键的问题”。 | 一个不做清单：本版本明确不做哪些功能。 |

阶段通过标准：

- 你能用一句话说清楚项目服务谁。
- 你知道用户现在不用你的产品时，用什么替代方案。
- 你能指出这个项目为什么值得发布，而不是只因为它已经做了一半。

## 1. 从小玩具到可发布小产品

目标：把“我做了个好玩的东西”变成“陌生用户能打开、理解、完成核心流程，并愿意给反馈”的小产品。

| 优先级 | 课程 | 你能学到什么 | 学完应产出什么 |
| --- | --- | --- | --- |
| 必学 | [学习地图](/zh-cn/stage-1/learning-map/) | 了解 Easy-Vibe 的整体学习结构，知道哪些内容是起步、哪些是产品化、哪些是进阶能力。 | 给自己标记一条 2 到 4 周的学习路径，避免到处补课。 |
| 必学 | [搭建产品原型](/zh-cn/stage-1/building-prototype/) | 从业务问题拆出页面、流程和核心功能，把功能堆叠改成用户能走通的主路径。 | 一张核心用户流程图，以及一个能完成主任务的 MVP。 |
| 必学 | [完整项目实战](/zh-cn/stage-1/complete-project-practice/) | 补齐等待、错误、反馈、模拟数据和迭代这些“像产品”的细节。 | 一个更完整的可试用版本，包含空状态、加载状态、错误状态和基础反馈。 |
| 选学 | [接入 AI 能力](/zh-cn/stage-1/integrating-ai-capabilities/) | 把文本生成、图像理解或图像生成接进产品流程，并理解 API、Key、调用和错误处理。 | 产品中至少有一个稳定可解释的 AI 能力，而不是只做一次性 demo。 |
| 加分 | [初级：学会 AI 编程工具](/zh-cn/stage-1/introduction-to-ai-ide/) | 系统熟悉 AI IDE 的使用方式，减少靠运气生成代码。 | 一套你自己的 AI 编程提示词和修复流程。 |

这一阶段的完成标准：

- 首页 5 秒内能让陌生人明白价值。
- 用户不用问你，也能完成一次核心流程。
- 产品不是“功能展示页”，而是围绕一个明确任务组织。
- 你知道第一批该找哪 5 到 20 个用户试用。

## 2. 从小产品到完整产品

目标：补齐真实产品需要的工程底座，包括界面、数据、接口、部署、版本管理、支付和质量检查。

| 优先级 | 课程 | 你能学到什么 | 学完应产出什么 |
| --- | --- | --- | --- |
| 必学 | [网页应用部署全面指南](/zh-cn/stage-2/backend/zeabur-deployment/) | 理解部署是什么，如何把项目放到公网，以及 Vercel、Netlify、Zeabur 等平台的基本差异。 | 一个任何人都能打开的公网链接。 |
| 必学 | [Git 与 GitHub 入门指南](/zh-cn/stage-2/backend/git-workflow/) | 掌握 clone、commit、push、pull、SSH 和 GitHub 仓库发布的基本流程。 | 一个公开或私有 GitHub 仓库，以及一次可回溯的发布记录。 |
| 必学 | [结合 Agent Skills 美化界面](/zh-cn/stage-2/frontend/llm-skills-beautiful/) | 学会用设计提示词和 Skills 改善 AI 默认生成界面的廉价感。 | 产品首页或主界面完成一次视觉重做。 |
| 必学 | [现代组件库与界面升级](/zh-cn/stage-2/frontend/modern-component-library/) | 理解组件库如何提升一致性、可维护性和专业感。 | 统一的按钮、表单、导航、卡片、弹窗或仪表盘组件。 |
| 必学 | [数据库与 Supabase 入门](/zh-cn/stage-2/backend/database-supabase/) | 从“刷新就没了”的本地状态，进入用户、数据、权限和持久化。 | 至少一张真实数据表，以及一个能读写数据的核心功能。 |
| 必学 | [大模型辅助接口开发](/zh-cn/stage-2/backend/ai-interface-code/) | 理解前后端如何通过 API 连接，如何让 AI 辅助写接口、文档和测试。 | 一个清楚的 API 设计，或者至少一个稳定的前后端连接点。 |
| 选学 | [Stripe 支付集成](/zh-cn/stage-2/backend/stripe-payment/) | 了解收费系统、支付流程、订单状态和 webhook 的基本逻辑。 | 如果项目适合商业化，产出一个测试支付流程。 |
| 必学 | [CLI Coding Agent 编程助手](/zh-cn/stage-2/backend/modern-cli/) | 用命令行 Agent 做更稳定的修复、重构、测试和发布前检查。 | 一份发布前检查流程：构建、测试、代码检查、手动验收。 |

发布检查清单：

- 有公开访问链接。
- 有清楚的登录或免登录体验路径。
- 有空状态、加载状态、错误状态。
- 有基础数据存储，不依赖浏览器刷新后“全没了”。
- 有反馈入口，例如邮箱、表单、GitHub issue、微信群或飞书表单。
- 有一个最小指标：访问量、注册数、使用次数、生成次数或留存。

## 3. 发布后的优化、数据与增长

目标：不是发布一次就结束，而是知道用户从哪里来、在哪里卡住、下一版该改什么，并把发布变成个人影响力资产。

| 优先级 | 课程 | 你能学到什么 | 学完应产出什么 |
| --- | --- | --- | --- |
| 必学 | [数据埋点](/zh-cn/appendix/5-data/data-tracking) | 记录用户访问、点击、生成、提交、退出等关键行为。 | 3 到 5 个关键事件，例如访问首页、点击开始、完成生成、提交反馈。 |
| 必学 | [数据分析](/zh-cn/appendix/5-data/data-analysis) | 用漏斗、留存、转化和分群理解产品是否真的变好。 | 一份发布后复盘：流量、完成率、反馈、下一步优先级。 |
| 选学 | [A/B 测试](/zh-cn/appendix/5-data/ab-testing) | 当你开始优化标题、按钮、定价和落地页时，学会用实验判断方案。 | 一个小实验计划，例如两个标题或两个 CTA 的对比。 |
| 加分 | [数据可视化](/zh-cn/appendix/5-data/data-visualization) | 把零散数据整理成能长期查看的仪表盘。 | 一个产品数据看板，哪怕最开始只用表格。 |
| 必学 | [技术写作](/zh-cn/appendix/9-engineering-excellence/technical-writing) | 用 README、发布说明和文章讲清楚作品价值，降低陌生人理解成本。 | 一篇 500 到 1000 字的发布短文。 |
| 必学 | [开源协作](/zh-cn/appendix/9-engineering-excellence/open-source-collaboration) | 理解 README、issue、license、贡献说明和 GitHub 展示方式。 | 一个更像正式项目的 GitHub 首页。 |
| 加分 | [Web 性能优化](/zh-cn/appendix/3-browser-and-frontend/web-performance) | 理解加载速度、资源体积和核心体验指标对传播转化的影响。 | 一轮性能检查和 2 到 3 个具体优化。 |

建议你每个发布项目都配一篇短文，结构固定为：

1. 我遇到或观察到什么问题。
2. 我做了什么产品来解决它。
3. 你可以在哪里试用。
4. 它现在还不完美，下一步会改什么。

## 5. 个人品牌与作品展示

目标：让别人能看见你、记住你，并通过你的作品理解你的能力。这一组直接服务于你“提升名气、吸引流量和注意力”的目标。

| 必学 | [选择合适的平台](/zh-cn/stage-3/cross-platform/choose-platform/) | 判断产品应该做网页、插件、PWA、桌面端、小程序还是移动端。 | 为你的 3 个候选项目各选一个最合适的发布形态。 |
| 选学 | [浏览器 AI 助手插件](/zh-cn/stage-3/cross-platform/browser-ai-extension/) | 开发更容易传播的浏览器插件类 AI 产品。 | 一个能在浏览器里使用的小插件原型。 |
| 选学 | [VS Code 插件](/zh-cn/stage-3/cross-platform/vscode-extension/) | 面向开发者用户做工具型作品，适合建立技术影响力。 | 一个面向开发者场景的插件作品。 |
| 选学 | [PWA 本地应用](/zh-cn/stage-3/cross-platform/pwa-local-app/) | 把网页工具做成可安装应用，降低用户使用门槛。 | 一个可安装到手机或桌面的轻量应用。 |
| 选学 | [Electron 桌面应用](/zh-cn/stage-3/cross-platform/electron-voice-to-text/) | 做更完整的桌面生产力工具，适合重度工作流产品。 | 一个桌面端工具的最小可用版本。 |

你的作品集建议分成三层：

- 小工具：解决一个窄问题，发布快，适合吸引第一批关注。
- 小产品：有完整流程和基础数据，适合长期迭代。
- 旗舰项目：最能代表你能力的项目，用于个人主页、简历和社交平台置顶。

| 必学 | [Figma 与 MasterGo 入门](/zh-cn/stage-2/frontend/figma-mastergo/) | 建立基础设计工具能力，用于封面、截图、落地页和产品结构设计。 | 一个产品封面或落地页视觉稿。 |

发布内容的最低配置：

- 一张产品截图。
- 一张带标题的分享图。
- 一个 30 到 60 秒演示视频。
- 一篇短发布说明。
- 一个可以立刻点击试用的链接。

| 必学 | [七款 AI 编程工具对比](/zh-cn/stage-1/appendix-articles/example0-1/vibe-coding-tools-snake-game-tutorial) | 通过贪吃蛇案例理解不同 AI 工具的生成差异和调试方式。 | 一份你偏好的游戏/互动开发工具选择。 |
| 必学 | [图形与动画](/zh-cn/appendix/3-browser-and-frontend/graphics-animation) | 理解动画、Canvas、SVG、渲染和互动体验的基础。 | 一个小动画或 Canvas 互动 demo。 |
| 必学 | [JavaScript 深入](/zh-cn/appendix/3-browser-and-frontend/javascript-deep-dive) | 掌握事件、状态、异步和运行时行为，支撑游戏逻辑。 | 一个包含计分、状态更新和用户输入的小作品。 |
| 选学 | [状态管理](/zh-cn/appendix/3-browser-and-frontend/state-management) | 管理复杂互动项目里的状态变化。 | 一套清晰的游戏状态或互动状态结构。 |
| 选学 | [PWA 本地应用](/zh-cn/stage-3/cross-platform/pwa-local-app/) | 把轻量小游戏或互动工具做成可安装应用。 | 一个可安装、可离线或半离线体验的小作品。 |

建议先做三类小作品：

- 一个 5 分钟能玩懂的小游戏。
- 一个能解释复杂概念的互动可视化。
- 一个带成就、积分、收藏或本地存档的轻量 PWA。

## 8. 你的 30 天发布计划

不要等“学完”再发布。用下面这个节奏做一个真实产品。

### 第 1 周：选题与收敛

- 从现有半成品里选一个最适合发布的项目。
- 看 [找到好点子](/zh-cn/stage-1/finding-great-idea/)、[Jobs to Be Done](/zh-cn/stage-1/appendix-jobs-to-be-done/) 和 [The Mom Test](/zh-cn/stage-1/appendix-mom-test/)。
- 写出目标用户、核心场景、核心流程和不做清单。

### 第 2 周：补齐产品体验

- 看 [搭建产品原型](/zh-cn/stage-1/building-prototype/)、[结合 Agent Skills 美化界面](/zh-cn/stage-2/frontend/llm-skills-beautiful/) 和 [现代组件库与界面升级](/zh-cn/stage-2/frontend/modern-component-library/)。
- 补齐首页、空状态、加载状态、错误状态和反馈入口。
- 找 3 个朋友或潜在用户试用，记录他们卡住的地方。

### 第 3 周：上线与基础数据

- 看 [网页应用部署全面指南](/zh-cn/stage-2/backend/zeabur-deployment/)、[Git 与 GitHub 入门指南](/zh-cn/stage-2/backend/git-workflow/) 和 [数据埋点](/zh-cn/appendix/5-data/data-tracking)。
- 部署到公网。
- 加最简单的访问统计或事件记录。
- 写一篇发布说明。

### 第 4 周：传播与迭代

- 看 [个人网页与学术博客](/zh-cn/stage-3/personal-brand/personal-website-blog/)、[技术写作](/zh-cn/appendix/9-engineering-excellence/technical-writing) 和 [数据分析](/zh-cn/appendix/5-data/data-analysis)。
- 做一张分享图和一个短视频。
- 发到朋友圈、X、即刻、掘金、少数派、GitHub 或你常用的社区。
- 收集反馈，做一次小版本迭代。

## 9. 建议你现在立刻开始的 7 节

如果你只想先启动，不想被庞大课程吓住，我建议按这个顺序：

1. [找到好点子](/zh-cn/stage-1/finding-great-idea/)：判断哪个半成品值得发布。
2. [用 Jobs to Be Done 找到用户真正想完成的事](/zh-cn/stage-1/appendix-jobs-to-be-done/)：把功能想法变成用户任务。
3. [搭建产品原型](/zh-cn/stage-1/building-prototype/)：把核心路径做清楚。
4. [网页应用部署全面指南](/zh-cn/stage-2/backend/zeabur-deployment/)：获得公网链接。
5. [结合 Agent Skills 美化界面](/zh-cn/stage-2/frontend/llm-skills-beautiful/)：解决“看起来不像正式产品”的问题。
6. [技术写作](/zh-cn/appendix/9-engineering-excellence/technical-writing)：写清楚你的作品。
7. [如何构建个人网页与学术博客](/zh-cn/stage-3/personal-brand/personal-website-blog/)：把多个作品沉淀成长期品牌资产。

这七节刚好对应你的主要断点：筛选、定位、产品化、上线、打磨、讲述、被看见。
